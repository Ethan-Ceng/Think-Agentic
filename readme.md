  ### 3. Agent Profile

  主要功能：

  - Agent 名称、头像和能力说明。
  - System Prompt。
  - 默认模型和参数。
  - 可用 Tools、Skills、MCP、A2A。
  - 权限与审批策略。
  - 创建任务时选择 Agent。
  - 克隆、启停和版本记录。

  现有 Agent、模型、Tools、Skills 设置可以逐步收敛到 Profile，而不是再建设一套重复配置。

  ### 4. 多 Agent

  主要功能：

  - 创建 Agent 团队。
  - 定义 Planner、Researcher、Coder、Reviewer 等角色。
  - 任务拆分与派发。
  - 并行子任务。
  - Agent 间上下文交接。
  - 子任务状态可视化。
  - 失败重试、取消和人工接管。
  - 汇总最终结果。
  - Trace 展示每个 Agent 的贡献和消耗。

  它应该依赖 Agent Profile，不能先做一组只有名字和头像的静态 Agent 卡片。

  ### 5. Knowledge 知识库

  主要功能：

  - 上传和解析文档。
  - 文档分段、索引和向量检索。
  - 知识库目录与权限。
  - 绑定 Project 或 Agent。
  - 检索过程与命中片段展示。
  - 回答中的结构化引用。
  - 文档更新、重建索引和删除。
  - 数据隔离与敏感内容控制。

  未来的“引用卡片”更适合成为 Knowledge 或 Deep Research 的组成部分。

  ### 6. 用户长期记忆

  主要功能：

  - 从对话中提出记忆候选。
  - 用户确认后保存。
  - 查看、搜索、编辑和删除。
  - 控制当前对话是否引用记忆。
  - 显示哪些回答使用了记忆。
  - 容量、过期和冲突处理。
  - 与 Session Memory、Knowledge 严格分离。

  这个功能的难点主要是隐私、错误记忆、冲突和可控删除，不只是增加一个侧栏。

  ### 7. 语音交互

  首期功能：

  - 录音权限。
  - 开始、暂停、取消。
  - 录音时长和状态反馈。
  - 上传并转写。
  - 转写结果进入输入框，允许编辑后发送。
  - 移动端适配和失败恢复。

  语音播放、实时双向语音、打断和降噪应放到后续阶段。

  ### 8. MCP UI Resource

  主要功能：

  - MCP Tool 返回结构化 UI Resource。
  - 表格、图表、表单和详情视图。
  - Resource 与 Tool Call、Session、Trace 关联。
  - 表单提交继续触发 Tool。
  - 高风险动作接入现有批准机制。
  - 不可信 HTML/脚本隔离。
  - 不支持 UI Resource 时降级为 JSON/文本。
  - 刷新后的状态恢复。

  它不是简单的前端组件库，需要同时设计 MCP 协议映射、安全沙箱、状态和 Tool 回调。

  建议的依赖顺序是：

  1. Project
  2. Agent Profile
  3. Knowledge
  4. 多 Agent
  5. 用户长期记忆

  Prompt 可以按实际需求插入；语音和 MCP UI Resource 是相对独立的大项目。当前最值得先深入比较的是 Project、Agent Profile 和 Knowledge。
